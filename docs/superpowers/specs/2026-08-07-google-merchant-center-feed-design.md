# Google Merchant Center — Product Feed, Returns Policy & Structured Data

**Date:** 2026-08-07
**Status:** Approved (design), pending implementation plan
**Author:** Santiago + Claude

## Goal

Get **Maky The Diva Flowers** approved on Google Merchant Center so its ~96 active
products appear in Google's **free product listings** (Shopping tab + Search),
without requiring paid Google Ads to start. Deliverables are the code pieces the
site needs; the Merchant Center account configuration is done by the owner in
Google's UI, guided by this project.

- **Business:** Diva Flowers / Maky The Diva Flowers, 1077 Willis Ave, Albertson,
  NY 11507. Studio phone `+1 (516) 484-3456`; mobile/WhatsApp `+1 (516) 851-2815`
  (owner's preferred channel: call/text/WhatsApp). Same-day cutoff 2:00 PM.

  dot**, so a feed URL ending in `.xml` is naturally exempt from the locale rewrite.
- **Legal pages:** `app/[locale]/legal/{privacy,terms}/page.tsx` use
  `getTranslations` (next-intl) + `LegalShell` + a `legal.*` namespace in
  `messages/{en,es}.json`. `terms` already has an internal `returns` section.
- ⚠️ **"This is NOT the Next.js you know"** (AGENTS.md): before writing the route
  handler and touching middleware, read the relevant guide under
  `node_modules/next/dist/docs/` (Route Handlers, `middleware`/`proxy` conventions,
  caching/`revalidate`). Do not assume the App Router API matches training data.

## Confirmed product decisions

1. **Delivery model:** local delivery only (Long Island). Shipping configured as a
   local-delivery service at the Merchant Center **account level** (not per-item in
   the feed).
2. **Pricing in feed:** one item per product using the **Standard** price
   (`startingPriceCents`), which already matches the structured-data `lowPrice` →
   no price mismatch.
3. **Feed language:** **English only**, linking to `/en/...` pages. (ES feed can be
   added later as a second feed.)
4. **Brand string:** **"Maky The Diva Flowers"** everywhere (feed + structured data),
   for consistency with the Merchant Center account and domain.

## Chosen approach

**Dynamic scheduled-fetch feed** (RSS 2.0 + Google namespace) generated by a Next.js
Route Handler. Merchant Center pulls it on a daily schedule. Rejected alternatives:
manual Sheet/TSV upload (drifts out of sync, manual per change) and Content API
(OAuth overkill for a near-static 96-item catalog).

## Piece 1 — Product feed route

**Endpoint:** `https://makythedivaflowers.com/merchant-feed.xml`
**File:** `app/merchant-feed.xml/route.ts` (segment name includes `.xml` so it (a)
serves at the clean URL and (b) is exempt from the intl middleware matcher).

**Behavior:**
- Import `PRODUCTS`; keep only `active: true`. (Do **not** apply `isInSeason` /
  `giftExtra` filters — the feed should list the full sellable catalog; revisit only
  if the owner wants seasonal hiding.)
- Emit RSS 2.0 XML: `<rss version="2.0" xmlns:g="http://base.google.com/ns/1.0">`
  with a `<channel>` (title, link, description) and one `<item>` per product.

**Per-item attributes:**

| Attribute | Source / value |
|-----------|----------------|
| `g:id` | `product.id` |
| `g:title` | `product.title.en` (≤150 chars) |
| `g:description` | `product.description.en`, plain text, ≤5000 chars (CDATA) |
| `g:link` | `${SITE.url}/en/product/${product.slug}` |
| `g:image_link` | `${SITE.url}${images[0].src}` (absolute) |
| `g:additional_image_link` | up to 10 more `images[n].src` (absolute) |
| `g:availability` | `in_stock` (all feed items are active) |
| `g:price` | `${(startingPriceCents(p)/100).toFixed(2)} USD` |
| `g:brand` | `Maky The Diva Flowers` |
| `g:condition` | `new` |
| `g:identifier_exists` | `no` (custom floral, no GTIN/MPN) |
| `g:google_product_category` | mapped by `product.category` (see below) |
| `g:product_type` | internal breadcrumb, e.g. `Flowers > Arrangements` |

**Category mapping (`google_product_category`):**
- `arrangements`, `bouquets`, `sympathy` → **Fresh Cut Flowers** (Google taxonomy
  ID `6248`).
- `plants` → **Home & Garden > Plants** (ID `985`).
- `gifts` → omit the attribute (let Google auto-categorize) or a generic default;
  refine later if disapprovals appear.
- `subscriptions` → not present in current active catalog; if added later, treat as
  Fresh Cut Flowers.

**XML safety:** wrap free-text fields (`title`, `description`, `link`) in `CDATA`
and/or XML-escape `& < >` to avoid malformed feed errors.

**Caching:** static-ish data → cache the response (e.g. `revalidate` per Next docs)
and set `Content-Type: application/xml; charset=utf-8`. Google fetches daily, so an
hourly-or-longer revalidate is fine.

**Shipping:** not emitted per-item. Configured at Merchant Center account level as a
local-delivery service (owner task).

## Piece 2 — Returns / refund policy page

**File:** `app/[locale]/legal/returns/page.tsx`, mirroring `terms/page.tsx`
(`getTranslations`, `LegalShell`, `alternates.languages`).
**Copy namespace:** add `legal.returns` to `messages/en.json` and `messages/es.json`
(bilingual). Reuse/align with the existing `terms.returns` wording so the two don't
contradict.

**Policy content (florist-appropriate, what Merchant Center requires):**
- Freshness guarantee: if flowers arrive damaged or not fresh, we replace or refund.
- Reporting window: report issues within 24–48 h with a photo.
- Substitution: flowers, container, or color may be substituted for equal or greater
  value when a specific stem is unavailable (standard florist practice).
- Cancellation/changes: allowed before the same-day **2:00 PM** cutoff / before the
  arrangement is made.
- Perishable nature: custom perishable goods; explain what is and isn't refundable.
- Contact to start a claim: **call/text/WhatsApp 516 851 2815** (owner's preferred
  channel), plus studio phone/email from `SITE`. Delivery area: Long Island (list
  `SITE.deliveryZones`).

**Wiring:** link the new page from the site footer (find the footer/legal-links
component and add `Returns` / `Devoluciones`). The public URL
`https://makythedivaflowers.com/en/legal/returns` is what the owner enters in
Merchant Center's return-policy settings.

## Testing / verification

- **Unit test** the feed generator (extract a pure `buildMerchantFeed(products)`
  function so it's testable without HTTP): asserts required attributes present,
  correct absolute URLs, price = Standard, only `active` products included, XML is
  well-formed and escapes special chars. Follow existing `tests/unit/*` (Vitest)
  patterns (see `tests/unit/product-helpers.test.ts`).
- **Route check:** fetch `/merchant-feed.xml` on the dev server → valid XML,
  `Content-Type: application/xml`, ~96 items, not redirected to `/en/...`.
- **Feed validation:** run the live URL through Merchant Center's feed diagnostics
  after deploy; expect item count ≈ 96 with no critical errors.
- **Returns page:** renders EN + ES, linked from footer, reachable at
  `/en/legal/returns`.
- **Structured data:** validate a PDP with Google's Rich Results Test; brand shows
  "Maky The Diva Flowers", price matches the feed.
